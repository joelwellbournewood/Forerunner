## Definitions

The triage of 2026-10-23 wrote "the definitions given in the task apply" and did not restate them;
the definitions below are the ones its rows applied (reconstructed from its justifications: "the
product is unusable on a release platform", "cross-human access", "a secret value reaches a card",
"borderline P1, kept P2 because limits still hold and a workaround exists") and are the ones this
re-read uses:

- **P0**: a release artefact cannot be installed or a release path crashes; persistent data is lost;
  one human's agent acts as, spends for or reads another human's data (a cross-human leak); a secret
  value reaches a log, a row or a model's context; a limit enforced in code can be bypassed from a
  prompt.
- **P1**: a core action the spec requires fails on a supported profile, or runs without the approval
  the spec requires, with no workaround or only a partial one.
- **P2**: a defect or gap with a bounded effect and a workaround; listed in the release notes.
- **Not a bug**: a design decision recorded in an ADR, a documented stand-in with a re-test row in
  BLOCKERS.md, or a record of a measurement or a closed finding.
- **Fixed since 2026-10-23**: the defect is gone from the code at 7ad6011 (verified), whether or not
  the doc entry still stands.
- **Being built / being fixed**: owned by a named item or by one of the agents working now (O.4's
  five findings, the late hooks approval of J.7/S.6, B.5's four lows, w4-stale-docs' three lows,
  the C.5 proposal tool, A.3, P.7/P.11); such entries are classified anyway and marked.

### What was hunted for, and where

- **Data loss.** The git host poller's at-most-once delivery (`runtime.md:3298–3300`) loses one
  event's inbox message on a crash, never a row; a queued phone upload over 2 MiB is dropped when
  the app closes before it is sent (`apps.md:1659–1660`, `apps/ui/src/mobile/uploads.ts:20`), the
  file stays on the phone; `fr setup --email` on a pre-ADR-0082 install can start a second human
  (`runtime.md:3140–3144`), the rows stay and `fr setup --human-id` binds back; the quiet-hours job
  slot and the held push notices are in memory (`runtime.md:3356–3359`, `state-service.md:437–440`),
  the records stay in the inbox. All P2.
- **A limit a prompt can bypass.** The hooks still run every check before every model and tool call
  (`packages/runtime/src/enforcement/hooks.ts:225–226, 386`); `ToolSpec.gate: "registry"` skips the
  autonomy hold only for registry command tools, which the registry's own card confirms by risk
  (`testing.md:1249–1254`); `StateApprovals` spends an always-human "yes" per call (`state-ports.ts:88–137`);
  the executor's third-attempt rung reads the project's `critic_ceiling` in every composition
  (`testing.md:1298–1307`). Nothing found.
- **A secret that can reach a log, a row or a model.** `scrubSummary` keeps `secret:` references and
  removes values (`hooks.ts:555–566`); the Cloudflare card shows the reference (w5-review-findings,
  2e3e382); the all-capitals `*KEY` rule fails closed (`platform-notes.md:89–92`). The install
  wrapping key `forerunner.install_wrap_key` is a plain vault entry (`packages/vault/src/wrap.ts:37`)
  that `vault.list()` returns; the only paths that put a name into a run's `grantedSecrets` are the
  session grant (`compose.ts:2282`: the GitHub token and the shared grants), an extension's
  human-approved `permissions.secrets` (`extensions/registry.ts:606–611, 921`) and the owner's own
  shared-secret proposal (`secrets/routes.ts:71–84`); no code refuses the name, no prompt can grant
  it. P2 (new row 50 below).
- **An action without the approval the spec requires.** A high-risk confirmation from the desktop
  works on a solo store (`compose.ts:2696, 2717–2735`; `loop-routes.test.ts:909`); the email mode
  change from the Settings page confirms on the page and writes an `email.settings` audit row but is
  not a registry command (no change-log row, no undo; `email.md:509–511`): an undo gap, not a missing
  approval, P2. The specialist and skill toggles (`extensions.md:333`) and the cloud voice toggle
  (O.4 medium) are inert in one direction each: no action runs that was not already configured by the
  human, so P2 as the triage classed `extensions.md` (7).
- **A cross-human leak.** The install binds by selector or refuses (`compose.ts:1110`, ADR 0082);
  `agent_private` rows never reach Postgres (ADR 0083, `memory.md:447–453`); the email routes fail
  closed without an identity port (`email.md:501–508`, ADR 0084); the remote pick-up is keyed on the
  owner (`cloud-runner/src/remote.ts`, triage row). The mirror's `secret_ref` is still not pinned
  (`projects-mirror.ts:734`), the token only ever goes to the GitHub API as a bearer: P2 as before.
- **A crash of a release path.** The release APK is signed and verified (`build.gradle.kts`,
  `scripts/android-apk-verify.mjs`, BLOCKERS "Android keystore" row: runs 39952987240, 40000764444,
  40013402240 passed the apksigner step); the Linux and Windows desktop builds run in `desktop.yml`;
  the emulator smoke's failure at the bottom-nav click is a driver problem on a Chromium 83 WebView
  (`apps.md:1610–1621`), not a crash of the app. The biometric prompt left on screen after the 45 s
  bound (`apps.md:1636–1641`) fails closed. P2.
