Forerunner Build Map

Forerunner is a desktop app that works as a persistent AI project manager. You describe a project; it drafts a plan, hands each task to a specialist AI agent, has a critic agent review the work, and keeps you in charge of the money and the decisions. This engagement started on 24 October 2026 with one goal from the owner: make the app actually work for a person, and make it easy to understand.

2 · The product

What Forerunner is made of

Everything runs on the person's own computer. The app talks to Claude (through the person's Claude subscription or an API key) and, if they want, to their GitHub repositories.

apps/desktop · apps/ui

The desktop app

The window, the tray and every screen: Home, a project's Overview and Tasks, the Inbox for questions and approvals, Talk (chat), Sessions, Costs and Settings.

packages/runtime

The engine

A local service that plans projects, runs work sessions, picks the next task, keeps budgets, and waits or goes on when a credential runs out.

specialists · critic

The AI agents

Specialists (coder, writer, researcher, tester and more) do the tasks; a separate critic reviews each one before it counts as done.

packages/billing

Money and credentials

Which Claude does the work, what each task and session may spend, what has been spent, always shown in CHF.

GitHub

Repositories

One repository is one project. Work arrives as pull requests the person can review and merge; two people can work on one repository together.

chat

Talk

Ask what happened, what is left or why something failed; give instructions in plain words. Chat remembers the project's history and thinks longer when a question needs it.

5 · Method

How the work is organised

The owner sets the goal and decides the product questions. Claude, as session lead, turns them into fix runs and reports back in plain words. A run is a set of areas; AI agents work on two areas at a time, each in its own copy of the code. Nothing reaches the main branch without its tests, an independent review and a green build on Windows and Linux.

  1. A failing testIt shows the problem where the person meets it: a click, a screen, a reply.
  2. The changeMade in its own copy of the code. A test is never weakened to pass.
  3. A bench walkThe real app on a stand-in AI, with screenshots before and after.
  4. Independent reviewAnother agent tries to break it and lists what blocks.
  5. Fix-up and mergeBlockers fixed, the full suite green, one merge at a time.
  6. CI greenWindows and Linux, plus the installed app in a real window.

8 · Risks and actions

What could slow it down, and what the owner can do

Risks

  • Weekly usage limit. At 79% of the week, with the owner's stop line at 90%. The sorting finishes if it stays under the line; the big fix run waits for the reset on Sunday 22 November, 05:00 UTC.
  • Machine restarts. The work machine restarted four times on 16–17 November. The pipeline now saves every stage and resumes, so a restart costs minutes, not hours.
  • What only the owner's PC can show. The owner's own Claude subscription and the real Windows desktop (tray, notifications) cannot be fully tested here; they go to the owner's checklist.

Owner actions

  • Nothing needed right now.
  • After the sorting: answer the few questions only you can decide, in one short set.
  • When convenient: delete the six merged backup branches on GitHub (keep plan-files) and create the forerunner-registry repository.
  • At the end: install the build on your PC and walk the five-step checklist.
